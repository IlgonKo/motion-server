# TD-046 PP/PV·Homing·모드 변경의 정지 상태 접수 제한

## 현재 상태

- 등록일: 2026-11-26
- 상태: `open`
- 이번 작업은 합의 사항 등록이며 구현은 진행하지 않는다.

## 문제와 현재 구현

PP/PV 명령 경로에는 운전 중 신규 명령을 거부하는 공통 정지 상태 검사가 없다.
기존 권한·Fault·Enable 등 검사를 통과하면 PP는 RxPDO 목표 위치를 변경하고
set-point handshake를 수행하며, PV는 RxPDO 목표 속도를 변경하여 전송한다.
PP handshake는 새 목표 접수 확인이지 이전 이동 완료 대기가 아니다.

확인 경로:

- `motion_server/handlers/command/motion.py`
- `motion_server/control/setpoint_output.py`
- `motion_server/handlers/command/jog.py`

현재 move_abs/move_rel에서는 일부 상태 검사 전에 Profile Velocity를 변경하므로,
단순히 마지막 전송 단계에 정지 검사를 추가하면 거부된 명령도 기존 운전에 영향을 줄 수 있다.

## 확정한 공개 계약

- PP 위치 명령(move_abs/move_rel), PV 속도 명령(move_vel), Homing 시작,
  명시적 모드 변경은 대상 축이 정지한 상태에서만 접수한다.
- `move_vel(0)`도 예외로 허용하지 않는다. 운전 중 정지는 기존 Stop 명령을 사용한다.
- 운전 중 제한 대상 요청은 기존 API Fail 계약으로 즉시 거부한다.
  명령 대기열, 자동 정지 후 실행, 자동 재전송은 제공하지 않는다.
- **Jog 동작만 접수 제한에서 제외한다.** 이미 Jog 모드인 상태에서는 운전 중에도
  Jog 방향/속도 갱신을 허용한다. 다른 모드에서 Jog로 진입하거나 Jog에서 다른 모드로
  전환하는 것은 정지 상태에서만 허용한다. jog_start 내부의 암묵적인 모드 변경도 동일하다.
  방향/속도 갱신을 위한 Panel 대기·재전송 로직은 만들지 않는다.
- Stop·Disable은 이 신규 정지 제한의 대상이 아니다. 기존 권한 등 별도 조건은 유지한다.
- CSP 운전의 명령 처리 변경은 범위에서 제외한다.
- 정지 상태 확인은 신규 명령 접수 조건이며 목표 도달·시퀀스 완료 판단 기능으로 확장하지 않는다.

## 구현 방향

- 제한 대상 요청은 어떤 목표값·Profile Velocity·mode·controlword·PDO·관련 cache도
  바꾸기 전에 검사한다. 이 제한으로 거부하면 기존 운전 명령을 보존한다.
- 다축 요청은 대상 전체를 먼저 검사하여 하나라도 운전 중이면 요청 전체를 거부한다.
  이는 접수 전 검사이며 다축 동기 제어·연계 정지·실장치 쓰기 실패의 transaction 보장을 추가하지 않는다.
- 정지 판정은 유효한 장치 feedback을 근거로 한다. Target Reached 또는 순간 속도 0만으로
  정지를 확정하지 않는다. 기존 장치 profile의 상태 의미를 재사용한다.
- 명령 접수 직후 아직 feedback이 정지로 남아 있는 구간에서 연속 명령이 통과하지 않도록 한다.
  필요한 내부 상태의 소유권·해제 조건은 구현 전 확정한다.
- 기존 예외/Fail 매핑과 Schema 설명, 사용자 문서 및 관련 시험을 함께 정리한다.
  새 public API나 backend capability는 이번 합의만으로 추가하지 않는다.

## 구현 전 확인할 세부 사항

1. 지원 장치별 정지 표시 및 feedback 유효성 조건, 신호 지연과 초기 상태 처리.
2. 접수 직후 보호 상태의 해제: 목표가 현재 위치인 명령, 실패, Stop, Fault, Disable,
   reconnect/restart, Homing 진행 중 정지 구간을 포함한다. 멈춰 보이는 중간 상태를
   신규 운전 가능으로 잘못 판단하지 않도록 기준을 확정한다.
3. 기존 Fail 코드와 사유/대상 축 정보 표현. 새 코드가 필요한지는 기존 계약을 먼저 확인한다.
4. CSP가 포함된 다축 요청이나 CSP 관련 모드 전환의 적용 경계.
   CSP 제외 합의를 임의로 변경하지 않고 구현 전에 범위를 확정한다.
5. 명시적 mode API뿐 아니라 Jog 내부 진입/이전 모드 복원에도 정지 조건을 적용한다.
   jog_stop의 정지 요청 자체는 즉시 허용하되, 이전 모드 복원은 실제 정지 확인 전에 실행하지 않는다.
   정지 요청과 모드 복원 순서·실패 처리는 구현 전 확인하며 새 Jog 명령을 자동 실행하지 않는다.

## 제외 범위

- 이미 Jog 모드에서 수행하는 방향/속도 갱신의 제한, 버튼 대기·자동 재전송 및 CSP 운전 변경.
- 자동 Stop/대기/재전송, 시퀀스 완료 판정, Trajectory Controller 확장.
- 일반 설정/파라미터 쓰기 전체에 대한 운전 중 제한 확대.
- 별도 지시 없는 Node-RED 시험 및 실장비 운전.

## 완료 조건

- 정지 상태에서 대상 PP/PV·Homing·모드 변경 요청은 기존 조건 충족 시 접수된다.
- 운전 중 각 제한 대상 요청과 move_vel(0)은 Fail이며 기존 목표·Profile Velocity·모드·PDO가 보존된다.
- 다축 요청의 일부 축 운전 중에는 어느 대상 축에도 요청 변경을 적용하지 않는다.
- 명령 직후 feedback 지연 구간의 연속 요청과 정지/Fault/복구 경계가 검증된다.
- Stop·Disable과 Jog 정지 요청은 차단되지 않으며, 이미 Jog 모드에서의 방향/속도 갱신을 허용한다.
- Jog 진입/이탈 및 암묵적 모드 변경은 운전 중 거부하거나 정지 후 복원하는 확정된 순서를 따른다.
  거부된 jog_start는 모드·목표·PDO를 변경하지 않으며 jog_stop은 정지 확인 전에 모드를 복원하지 않는다.
- CSP 회귀에서 기존 동작이 유지되며 API 문서에 접수 조건과 제외 범위가 일치한다.
