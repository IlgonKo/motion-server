# RF-011 Windows Service 등록 및 파일 로그 옵션

- 상태: `planned` (정책·등록 기본값 확정, 구현 미착수)
- 결정 갱신: 2026-11-24

## 사용자 가치

배포된 Motion Server 실행 파일을 직접 사용하거나 등록 스크립트로 Windows 서비스에 등록한다.
등록 이후 서비스 운영과 설정 변경은 사용자가 Windows 기본 관리 기능으로 수행한다.
콘솔/서비스/Linux 공통으로 선택적 비동기 파일 로그를 제공한다.

## 확정 범위

- 사용자에게 제공하는 실행 경로는 motion_server.exe 직접 실행과 서비스 등록 스크립트 두 가지다.
- Windows Manager, 미니 GUI, 별도 백그라운드 관리 프로그램, PID 선택/편입, GUI 재접속 및 windows_manager.json은 구현하지 않는다.
- Motion Server 자체에 Windows 서비스 진입점이나 Windows 종속 코드를 추가하지 않는다. Linux Docker와 Windows에서 공통 서버 실행 계약을 유지한다.
- 서비스 구동 방법은 아래 구현 기술 검증에서 구체화한다. 보조 도구의 채택과 패키지 포함은 검토 결과로 정하며 별도 사용자 관리 제품이나 콘솔 실행 감시 기능으로 확장하지 않는다.
- 콘솔/서비스 모두 같은 실행 파일·기존 패키지 config.txt·device catalog를 사용한다. 등록 스크립트는 서버 설정을 편집하거나 별도 복사본을 만들지 않는다.
- 파일 로그는 실행 모드와 독립된 선택 기능이다. 로그 설정은 사용자가 .env/config.txt에서 관리한다.

## 서비스 등록 스크립트 계약

1. 관리자 권한, 패키지 실행 파일 및 최종 선정한 서비스 구동 방식에 필요한 항목을 확인한다.
2. 약속한 서비스 이름이 이미 있는지 확인한다.
3. 기존 서비스가 중지 상태가 아니면 먼저 수동 중지하도록 안내하고 변경 없이 종료한다. 스크립트에서 Stop이나 강제 종료를 수행하지 않는다.
4. 중지된 동명 서비스가 있으면 삭제한다. 삭제가 완료되지 않거나 실패하면 이유를 표시하고 신규 등록을 진행하지 않는다.
5. 동명 서비스가 없거나 삭제가 완료되면 패키지 경로와 미리 정한 기본 설정으로 신규 등록한다.
6. 등록 결과를 표시하고 종료한다. 등록 직후 서비스를 자동으로 시작하지 않는다.

- 재등록은 기존 서비스 설정을 유지하는 갱신이 아니라 기본 설정으로 교체하는 작업이다. 사용자가 변경한 서비스 계정·시작 유형·복구 설정 등은 보존하지 않음을 안내한다.
- 삭제 후 신규 등록이 실패하면 실패 단계와 원인을 표시한다. 성공으로 보고하거나 서버를 임의 실행하지 않는다.
- 등록 후 시작·중지·재시작·상태 확인·설정 변경은 사용자가 Windows 서비스 관리 화면 등 기본 도구로 수행한다.
- 별도의 서비스 운영 명령 모음, 관리 GUI 및 자동 PID 탐색 기능은 제공하지 않는다.

## 서비스 기본 설정 및 실행 경계

| 항목 | 등록 기본값 |
| --- | --- |
| 서비스 이름 | `MotionServer` |
| 표시 이름 | `Motion Server` |
| 시작 유형 | 자동 |
| 등록 직후 실행 | 시작하지 않음 |
| 실행 계정 | `LocalSystem` (구현 시 접근 권한 검증) |
| 첫 번째 실패 | 5초 후 서비스 재시작 |
| 두 번째 실패 | 5초 후 서비스 재시작 |
| 이후 실패 | 아무 작업도 하지 않음 |
| 실패 횟수 초기화 | 1일 |

- 위 기본값은 사용자 합의로 확정했다. 등록 이후 변경은 사용자가 Windows 서비스 속성에서 수행한다.
- 부팅 자동 시작 기본값은 유지하되 등록 스크립트 실행 직후 Start는 하지 않는다. 이후 시작 유형은 사용자가 변경한다.
- 장애 복구는 Windows 서비스 기본 복구 설정으로 처리한다. 별도 감시 프로그램이나 자체 재시작 카운터를 만들지 않는다.
- 기존 Manager 설계의 '30분 연속 실행 시 횟수 초기화'와 최대 3회 재시작 정책은 위 Windows 서비스 기본 복구 설정으로 대체한다. 5초 간격 2회 재시도 후 추가 자동 재시작을 하지 않으며, 1일 초기화는 Windows 서비스의 실패 횟수 초기화 의미를 따른다.
- Bus Fault나 초기화 실패 상태로 서버 프로세스가 살아 있는 경우 이를 이유로 자동 재시작하지 않는다.
- 사용자 서비스 Stop은 기존 서버 정상 종료 경로로 전달한다. 정상 종료 대기는 최대 30초이며 초과 시 기록 후 관리 대상 서버를 강제 종료한다. Stop 후 자동 재실행하지 않는다.
- 서비스 Stop 후 서버를 다시 실행하지 않는다. 자체 Restart 추적 기능을 별도 구현 범위로 추가하지 않으며, 선정 도구와 기존 API 사이의 제약이 발견되면 기록하고 별도로 논의한다.
- 서비스는 LocalSystem을 기본 계정으로 구현하고 파일/Npcap 접근 권한을 검증한다. pywin32·특정 wrapper는 아직 채택하지 않았다. 검증 결과 기존 합의 변경이 필요한 경우에만 다시 논의한다.

## 파일 로그 정책 — 기존 합의 유지

### 파일 로그

- 시작·종료, 초기화 실패, 연결·제어권, 명령 실패, Fault 및 복구를 기록한다.
- 정상 명령·상태 로그의 기록 여부는 기존 활성화 설정을 따른다.
- 전용 worker에서 파일을 기록한다. 버스 주기에서 파일 write/flush를 기다리지 않는다.
- 설치 폴더와 분리된 저장 경로를 설정하며 파일 기록만 추가 옵션으로 활성화한다.
- 콘솔 실행에서는 기존 기능별 로그 설정으로 활성화된 로그를 항상 콘솔에 출력한다. 별도의 `MOTION_SERVER_LOG_CONSOLE_ENABLED` 설정은 만들지 않는다.
- 콘솔 실행에서 파일 기록을 켜면 콘솔과 파일 양쪽에 기록한다. 서비스 실행은 콘솔 창 없이 동작하며, 파일 기록은 활성화한 경우에만 수행한다.
- 시간·로그 수준·내용을 포함한 일반 텍스트를 사용한다.
- 크기 기준 rotation을 사용한다. 기본은 파일당 10 MB, 이전 파일 10개 보존이다.

### 실패 처리

- 파일 로그는 콘솔/서비스 모두 선택 기능이다. 서비스 모드에만 로그 기동 조건을 추가하지 않는다.
- 활성화된 파일 로그의 초기 열기 실패와 운전 중 디스크 부족/쓰기 실패 모두 Motion Server 실행을 중단하지 않는다. 사용 가능한 진단 경로로 알리고 아래 비동기 재시도 정책을 동일하게 적용한다. 콘솔 모드에서는 콘솔에 오류를 표시한다.
- Windows Event Log는 확정된 알림 경로가 아니다. 서비스 모드의 오류 알림 경로는 서비스 실행 보조 도구 검토에서 다루며 공통 서버에 Windows 종속 기능을 추가하지 않는다.
- 로그 대기열이 포화되면 버스 처리를 기다리게 하지 않고 가장 오래된 로그부터 버린다. 유실 개수를 집계해 기록 가능해지면 알린다.

### 비동기 로그 세부 정책 — 확정

- 대기열은 최대 10,000건이며 포화 시 가장 오래된 로그부터 버리고 유실 건수를 집계한다.
- 초기 파일 열기 또는 파일 쓰기 실패 시 worker에서 5초 간격으로 파일을 다시 연다. 실패 중 새 로그도 제한된 대기열에 보관하며 같은 포화 정책을 적용한다.
- 최초 실패를 알리고 동일 오류가 지속되면 60초마다 최대 1회 알린다. 복구 시 복구 사실과 누적 유실 건수를 파일에 기록한다.
- 종료 시 남은 로그 기록을 최대 3초 기다린다. 이는 전체 정상 종료 제한 30초 안에 포함하며 별도로 연장하지 않는다.
- 종료 대기 초과 시 남은 로그 수를 가능한 진단 경로에 알리고 종료를 진행한다.
- 파일 쓰기·재시도·오류 알림은 worker에서 처리하며 버스 주기가 기다리지 않도록 한다.
- 위 수치들은 내부 기본값으로 둔다. 사용자 설정은 파일 활성화·경로·파일 크기·보존 개수만 노출한다. 별도 전역 로그 수준 설정은 추가하지 않고 기존 기능별 로그 활성화 정책을 유지한다.

### 파일 설정 및 기동 조건 — 확정

```ini
MOTION_SERVER_LOG_FILE_ENABLED=0
MOTION_SERVER_LOG_FILE_PATH=
MOTION_SERVER_LOG_FILE_MAX_BYTES=10485760
MOTION_SERVER_LOG_FILE_BACKUP_COUNT=10
```

- 파일 기록 활성화 시 경로는 필수다. 절대 경로 또는 메인 설정 파일 위치 기준 상대 경로를 사용한다.
- 부모 폴더가 없으면 자동 생성한다. 지정 파일을 현재 로그로 쓰고 이전 파일은 `.1`부터 `.10`까지 보관한다(기본 보존 개수 기준).
- 재기동 시 기존 파일에 이어 쓰고 크기 제한 도달 시 순환한다.
- 서버 인스턴스마다 별도 파일을 사용한다. 같은 파일의 중복 사용은 거부한다.
- 콘솔/서비스 모두 파일 기록은 선택 사항이며 비활성화 상태에서도 실행할 수 있다. 비활성화 상태에서는 파일 경로를 요구하지 않는다.
- 초기 파일 열기 실패 시에도 서버 실행을 유지하고 오류 알림·비동기 재시도를 수행한다. 콘솔/서비스에 동일하게 적용하며 등록 스크립트는 로그 설정이나 파일 열기 가능 여부를 등록 조건으로 검사하지 않는다.
- 별도 전역 로그 수준 설정은 만들지 않고 기존 기능별 로그 활성화 설정을 유지한다.

## 구현 중 기술 검증 사항

- 사용자에게 추가로 결정받을 정책은 없다. 아래 항목은 구현 과정에서 확인하며, 기존 합의나 서버 책임 경계를 바꿔야 하는 문제가 있을 때만 다시 논의한다.

- Motion Server 자체를 변경하지 않고 기존 실행 파일을 Windows 서비스로 구동할 방법을 검토한다. 필요한 보조 도구와 패키지 포함 여부는 검토 결과에 따라 확정한다.
- 기존 Motion Server 실행 파일을 Windows 서비스로 실행하고, Windows에서 중지했을 때 서버도 종료할 수 있는 기존 도구를 선정한다.
- 확정한 등록 기본값의 적용과 패키지 작업 경로·필요 종속 서비스 연결을 확인한다.
- LocalSystem 계정의 실행 파일·설정·카탈로그 읽기, 활성화된 로그·가상장치 저장소 쓰기 및 Npcap 접근 권한을 검증한다.
- 서비스 모드에서 파일 로그 실패를 알릴 진단 경로. 공통 서버에 Windows 전용 기능을 추가하지 않는다.
- 숨겨진 콘솔·Job Object는 채택된 구현 방식이 아니다. Manager용 GUI 통신·PID 수동 편입·GUI 재접속 검토는 취소한다.

## 구현 및 패키징 범위

- 공통 비동기 파일 로그와 설정 연결을 구현한다.
- Windows 배포 패키지에 서버 실행 파일과 교체 등록 스크립트를 제공한다. 보조 도구 및 필요한 의존성의 패키지 포함 여부·방식은 위 검토 결과에 따라 확정한다.
- 등록 기본값과 재등록 시 설정 초기화, 수동 중지 후 재등록 절차, Windows 서비스 관리 화면에서 운영하는 방법을 문서화한다.
- RF-006 배포 검증 및 RF-010 사용자 문서에 해당 내용을 연결한다. 설치 경로·서비스 식별자는 기존 TD-019/TD-020 정리와 일치시킨다.

## 검증 및 완료 조건

- 서비스가 없는 경우 신규 등록되고 자동 실행하지 않는다.
- 중지된 동명 서비스는 삭제 후 기본값으로 재등록된다. 기존 사용자 서비스 설정이 남지 않는다.
- 실행 중 또는 전환 중인 동명 서비스는 자동 중지/삭제하지 않고 수동 중지를 안내한다.
- 권한 부족·누락된 패키지·삭제 대기·신규 등록 실패를 명확하게 보고한다.
- Windows 기본 관리 도구를 통한 시작·중지와 재부팅 자동 시작, 기본 복구 설정을 검증한다.
- 선정 도구로 서비스 실행 및 Windows에서 중지 시 서버 종료를 확인한다. 정상 종료/제한 시간은 별도 시험 환경에서 검증하며 실제 운영 서버는 사용하지 않는다.
- 콘솔과 서비스가 동일 설정으로 같은 axis/I/O 구성을 사용한다.
- 로그 활성화/비활성화, rotation/retention, 초기 열기 실패·운전 중 쓰기 실패·대기열 포화·복구·종료 대기를 검증한다.
- 완료 증거는 등록 기본값 표, 등록/수동 운영 시험 기록, 패키지 manifest 및 대표 로그로 남긴다.

## 범위 변경 기록 — 2026-11-24

- Windows Manager를 제거하고 서비스 교체 등록 스크립트 제공으로 단순화했다. 이전 GUI/백그라운드 관리 및 Manager 설정 파일 관련 합의는 이 결정으로 대체한다.
- 파일 로그 정책은 유지한다. 서비스 등록 이후 운영과 설정 변경은 사용자 책임이다.
- 앞서 정상 종료/Restart 경로의 코드·공식 문서를 조사했으나 별도 시험 프로세스 검증은 수행하지 않았다. 실행 검증 완료로 취급하지 않는다.
- 현재 작업은 문서 정리이며 코드 구현이나 서비스 설치/조작은 수행하지 않았다.
