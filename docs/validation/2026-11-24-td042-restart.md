# TD-042 동일 프로세스 Restart 검증 — 2026-11-24

## 결과

TD-042 구현 범위를 완료했다. 프로그램 코드 hot reload는 지원하지 않으며 Windows/Linux
공통 Application에서 설정과 세션만 새로 생성한다. 실행 기반 검증은 Windows에서 수행했다.

## 확인한 계약

- 파일/장치 설정 재로드, 최초 CLI 및 환경변수 우선순위 유지, 새로운 Diagnostic 생성.
- Success는 요청 수락이다. 이전 연결의 미완료 응답은 연결 종료로 실패할 수 있다.
- 접수된 저장은 마친 뒤 이전 저장 worker를 닫는다. Restart 이후 저장값 복원 및 OS 잠금 재사용.
- 이전 제어권 자동 복원 없음. 재접속 후 명시적으로 요청해야 한다.
- 정상 → 잘못된 설정/degraded → 정상, Bus 초기화 실패 → 정상 복구.
- 새 listener 포트 점유 시 이전 포트로 되돌아가지 않고 종료 코드 1.
- 반복 시 PID 동일, 세션 종료 후 저장 worker 잔존 없음, 로그 worker 중첩 없음.
- 자원 정리 실패와 로그 worker 미종료는 새 세션 시작을 막는다.
- 설정 재로드 중 종료 신호는 새 세션 실행을 막는다.

## 실제 Windows 서비스

새 패키지 `.codex_output/td042-package`로 중지된 시험 서비스를 교체했다.
Mock 한 축과 전용 로그/SQLite만 사용했으며 실제 장비에 연결하지 않았다.

- wrapper PID **21216**, 서버 PID **33032**.
- 연속 API Restart 5회마다 정상 초기화, PID 유지, 서비스 Running 및 제어권 초기화 확인.
- 설정 오류 시 degraded 실행, 수정 후 Restart 시 Diagnostic normal 복귀.
- TCP Port **65451 → 62880** 변경 후 같은 PID로 신규 포트에서 정상 응답.
- 마지막 Restart 수락 직후 서비스 Stop. 종료 후 6초 동안 Stopped, 서버 PID 잔존 0개.
- 서비스는 Automatic/Stopped로 남겼다. 다음 부팅 시 시험용 Mock 서버가 실행된다.

## 시험 도구 수정 및 범위

전체 회귀의 서버 모듈 reload로 예외 클래스 참조가 달라지는 문제는 테스트에서 현재 모듈을
참조하도록 수정했다. TCP 시험의 Windows 출력 인코딩을 UTF-8로 명시하고, Bus 실패 주입에는
실제 실패 계약의 EtherCATDiscoveryException을 사용했다. 서버 오류를 숨기기 위해 검증을 제거하지 않았다.

재부팅은 사용자 지시로 제외했다. 실장비 이동, Windows 주기 성능, Node-RED 시험은 하지 않았다.
Linux 실행 시험은 이번에 수행하지 않았다. 테스트 소스와 공통 구현은 플랫폼 분기를 추가하지 않았다.
