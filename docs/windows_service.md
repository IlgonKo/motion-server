# Windows 서비스 등록과 파일 로그

Motion Server를 직접 실행하거나 Windows 서비스로 등록할 수 있다. 등록 후 운영은
Windows 서비스 관리 화면(`services.msc`)에서 수행한다. 별도 Manager는 제공하지 않는다.

## 등록

1. 패키지의 `config.txt`와 장치 설정을 준비한다. 직접 실행으로 설정을 먼저 확인한다.
2. 직접 실행한 서버와 동명 서비스가 실행 중이면 사용자가 중지한다.
3. 관리자 PowerShell에서 패키지 폴더로 이동하고 다음 명령을 실행한다.

```powershell
powershell -ExecutionPolicy Bypass -File .\register_service.ps1
```

스크립트는 중지된 `MotionServer` 서비스가 있으면 삭제하고 기본값으로 새로 등록한다.
기존 서비스가 실행 중이거나 중지 중이면 변경하지 않고 수동 중지를 안내한다.
등록 완료 후 자동 실행하지 않는다. `services.msc`에서 **Motion Server → 시작**을 선택한다.

재등록하면 사용자가 변경한 서비스 계정·시작 유형·복구 설정이 기본값으로 바뀐다.
삭제 대기 오류가 나오면 서비스 속성 창 등을 닫고 다시 시도한다. 삭제 후 신규 등록이
실패했다면 원인을 해결하고 스크립트를 다시 실행한다.

## 기본값과 운영

| 항목 | 기본값 |
| --- | --- |
| 이름 / 표시 이름 | `MotionServer` / `Motion Server` |
| 시작 유형 / 계정 | 자동 / LocalSystem |
| 첫 번째·두 번째 실패 | 각각 5초 후 서비스 재시작 |
| 이후 실패 | 아무 작업도 하지 않음 |
| 실패 횟수 초기화 | 1일 |
| 종료 대기 | 최대 30초, 이후 강제 종료 |

시작·중지·재시작과 설정 변경은 Windows 서비스 화면에서 수행한다.
서비스로 실행할 때도 패키지의 동일한 서버 실행 파일·config.txt·장치 catalog를 사용한다.
패키지 경로를 옮기면 서비스를 수동 중지하고 새 경로에서 재등록한다.
LocalSystem이 패키지를 읽고 로그·가상장치 저장 경로에 쓸 수 있어야 한다.
실제 EtherCAT 사용 시 Npcap 설치와 해당 인터페이스 접근도 필요하다.

`system/server/restart`는 같은 PID에서 서버 전체를 재초기화한다. Windows 서비스는 실행 중
상태를 유지하며 기존 TCP 연결과 제어권은 해제된다. Success는 요청 수락이며 재접속 후
`system/server/status`로 완료 여부를 확인한다. 설정 파일은 다시 읽지만 프로그램 코드는
다시 로드하지 않는다. 실행 파일 업데이트 적용은 Windows 서비스 화면에서 중지·시작한다.

## 파일 로그

메인 `config.txt`에서 설정한다. 소스 실행은 메인 `.env`에 같은 키를 사용한다.

```ini
MOTION_SERVER_LOG_FILE_ENABLED=1
MOTION_SERVER_LOG_FILE_PATH=logs/motion_server.log
MOTION_SERVER_LOG_FILE_MAX_BYTES=10485760
MOTION_SERVER_LOG_FILE_BACKUP_COUNT=10
```

- 기본은 비활성화다. 서비스 실행에도 파일 로그는 필수가 아니다.
- 상대 경로는 메인 설정 파일 위치 기준이다. 부모 폴더는 자동 생성한다.
- 기존 파일에 이어 쓰며 기본 10 MiB, 이전 파일 `.1`~`.10`을 보존한다.
- 동일 로그 파일을 두 서버가 동시에 기록하지 못하도록 잠근다. `.lock` 파일이 남아 있어도
  프로세스가 종료됐으면 OS 잠금은 해제된다. 실행 중 잠금 파일을 삭제하지 않는다.
- 파일 열기/쓰기 실패에도 서버는 계속 실행한다. 5초마다 재시도하며 10,000건 대기열이
  차면 오래된 항목을 버린다. 복구 시 유실 건수를 기록한다.
- 콘솔 실행에서는 기존 활성화 로그를 콘솔에도 표시한다. 서비스에서는 WinSW가 서버 stdout/stderr를
  별도 파일로 복제하지 않는다. 서버 파일 로그의 오류 알림은 stderr로 출력되므로 서비스 모드에서는
  즉시 보이지 않을 수 있으며, 기록이 복구되면 파일에 복구 사실이 남는다.
- WinSW 자체 실행 오류 기록은 서버 파일 로그와 별개다. `Tools/service`의 wrapper 진단 기록 및
  Windows 이벤트 로그를 확인한다. 서버 파일 로그를 켜는 설정으로 대체되지 않는다.

## 패키지와 검증 범위

`Tools/service`의 WinSW 2.14.0 x64 실행 파일, 기본 XML, 의존성 정보, 라이선스는
빌드 시 포함된다. 다운로드는 SHA-256으로 검증한다. 등록은 다운로드 없이 실행한다.
사용자는 `register_service.ps1`을 이용하며 WinSW 명령을 직접 사용할 필요는 없다.

자동 시험은 등록 명령을 모의 실행한 것이며 실제 서비스 설치·LocalSystem 실행·부팅 자동 시작·
장애 복구·실제 Npcap 접근의 인수 완료를 의미하지 않는다. 이 항목들은 별도 Windows 시험 환경에서 확인한다.

2026-11-24 후속 시험에서는 실제 SCM 등록·LocalSystem Mock 실행·로그/영구 저장소 접근·
장애 복구·종료 제한을 확인했다. Npcap은 LocalSystem 시험 프로그램의 NIC open/close까지
확인했으며 실장비 동작 시험은 아니다. 재부팅 시험은 사용자 지시로 제외했다.
상세 범위는 [RF-011 검증 기록](validation/2026-11-24-rf011-review.md)을 참조한다.
